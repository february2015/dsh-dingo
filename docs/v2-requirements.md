# dsh-dingo 2.0 需求文档（卡片 1:1 会话常驻 + 四状态）

> 状态：规划稿 · 2026-08-16
> 目标版本：2.0.0（当前 1.0.0 为"事件驱动卡片"基线）

## 1. 背景与目标

1.0 的卡片是**事件驱动**的：对话出结论（有回复/需回答/失败）时才出现一张卡片，一个对话可能产生多张卡片。

2.0 改为**会话 1:1 常驻**：**只要是活跃的对话（正在执行或已出结论），卡片区域就有一张属于它的卡片**，实时反映该对话的状态，自动排序。用户不用打开每个对话就能在卡片区域看到"哪些对话在跑、哪些已出结论、哪些在等我"。

## 2. 核心概念：卡片 = 对话（1:1）

- 每个活跃对话**一张卡片**，卡片与对话一一对应；
- 同一对话的状态变化**更新同一张卡片**（不再产生多张）；
- 卡片区域 = 当前所有活跃对话的状态总览。

## 3. 四种状态定义与流转

| 状态 | 含义 | 图标 |
|---|---|---|
| **正在执行** | 对话正在运行（本轮 turn 未结束，agent 仍在干活） | **动态小圆环**（spinner，动画风格参考 DSH 自己的 loading 指示） |
| **有答案** | 本轮完成（turn/end completed）且无需回答 | 🟩 绿方块 |
| **有疑问** | 需要你回答（ask_user / 审批 / questions / 回复含疑问） | 🟠 问号 |
| **有异常** | 任务失败 / 异常结束 | 🔴 感叹号 |

**状态流转**：正在执行 →（turn/end 或提问）→ 有答案 / 有疑问 / 有异常。

## 4. 显示与隐藏规则

**显示**：所有活跃对话（四态都显示），包括：
- 其他对话：四态全显示；
- 当前对话的**正在执行**态：**仍显示**（例外，见下）。

**隐藏（结论态）**：用户点击卡片进入该对话（变成当前对话）后，**结论态（有答案/有疑问/有异常）卡片隐藏**——该对话的所有状态用户已看到，无需再占卡片位。

**例外（执行态）**：**正在执行的对话，即使点进去看（变成当前对话），执行态卡片仍然显示**——因为本轮还没执行完，用户需要持续看到它还在跑。只有它**完成并变成结论态**后，若仍是当前对话，才隐藏。

**小结**：
| 卡片状态 | 非当前对话 | 当前对话（点进去后） |
|---|---|---|
| 正在执行 | 显示 | **仍显示**（未完成） |
| 有答案/有疑问/有异常 | 显示 | **隐藏**（已完成） |

## 5. 自动排序

- **分组**：结论态（有答案/有疑问/有异常）排在**前面**；正在执行排在**后面**；
- **结论态内部排序**：提案为 有疑问 > 有异常 > 有答案（按"需要你处理的程度"），同状态内按最新更新时间倒序；（待确认，见 §9）
- **动态迁移**：正在执行的对话完成后，卡片**自动从"执行组"移到"结论组"**（图标切换 + 跑到前面）。

## 6. 卡片交互（延续 1.0）

- **点击** → 直达该对话（sessions.open）；按 §4 规则隐藏/保留；
- **× 关闭** → 手动关闭该卡片（语义待确认，见 §9）；
- 拖动：1.0 已禁用，2.0 保持禁用；
- 卡片不自动消失（延续 1.0.15）。

## 7. 与 1.0 的差异对照

| 项 | 1.0 | 2.0 |
|---|---|---|
| 出现时机 | 出结论/提问/失败时 | 会话一活跃（开始执行）即出现 |
| 卡片数量 | 每事件一张（同会话可多张） | 每会话一张（1:1） |
| 状态 | 结论三态 | 四态（+正在执行动画） |
| 排序 | 按出现时间堆叠 | 自动分组排序（结论前、执行后） |
| 当前对话 | 不显示卡片 | 结论态隐藏；**执行态仍显示** |
| 消失 | 点击跳转（清该会话）/ × 关闭 | 同左 + 点入后结论态隐藏 |

## 8. 联动（声音 / 系统通知 / 去重）

- **声音**：正在执行**不响**（安静）；状态变化（执行→结论）时按结论类型响（当/当当/咚，沿用 1.x 判定）；
- **系统通知**：DSH 不在前台时，状态变化（执行→结论/提问）发系统通知（沿用 1.x 的 osascript / Windows toast + 可见性抑制）；
- **去重**：卡片 1:1 后，同会话同轮内多次状态刷新只更新同一卡片；"同内容 10s 去重"是否保留待确认（建议：结论态一轮内去重保留；跨轮/状态变化总是更新）。

## 9. 未决问题（需用户确认）

1. **结论态内部排序**：有疑问 > 有异常 > 有答案？还是按时间？还是按会话创建顺序？
2. **× 关闭的语义**：a) 永久隐藏该会话（本轮不再出现）？b) 仅移除卡片，会话再有状态变化重新出现？c) 执行态卡片能否 × 关闭？
3. **去重窗口**：1:1 卡片下，"同内容 10s 去重"是否还需要（建议保留，防同轮重复提问刷屏）；
4. **卡片数量上限**：多对话并行时卡片无上限全显示，还是设上限（如最多 N 张，超出折叠"+N"）？
5. **执行态点击进入**：进入后执行态卡片仍显示（§4），但用户可能想在当前对话里也保留"回到执行卡片"的入口？还是纯常驻即可。

## 10. 技术要点（实现方向）

- **host 会话状态跟踪**：从 `session/event` 推导每会话状态（turn/start → 执行中；turn/end/ask_user/approval/questions → 对应结论态），维护"会话 → 状态"映射；
- **卡片数据源**：新快照形状 = **每会话一张卡片**（状态 + 会话/工作区信息 + 更新时间），替代"事件队列快照"作为卡片渲染源；
- **client 渲染**：四态图标（含 spinner 动画）、分组排序、点入隐藏/执行态保留逻辑、1:1 更新；
- **兼容改造**：1.0 的 feedback 引擎（声音/判定/去重/DND）、系统通知、深链直达继续复用，卡片层重构；
- **会话生命周期**：会话销毁/删除 → 对应卡片移除。

## 11. 验收标准（草拟）

- [ ] 对话开始执行 → 卡片区域出现该对话的执行态卡片（spinner 动画）
- [ ] 执行完成 → 同一张卡片变结论态并自动排到前面
- [ ] 同一对话全程只有一张卡片（1:1）
- [ ] 点卡片进入结论态对话 → 卡片隐藏；进入执行中对话 → 卡片保留
- [ ] 声音/系统通知/直达行为与 1.x 一致
