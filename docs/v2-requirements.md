# dsh-dingo 2.0 需求文档（卡片 1:1 会话常驻 + 五状态）

> 状态：规划稿 · 2026-08-16
> 目标版本：2.0.0（当前 1.0.0 为"事件驱动卡片"基线）

## 1. 背景与目标

1.0 的卡片是**事件驱动**的：对话出结论（有回复/需回答/失败）时才出现一张卡片，一个对话可能产生多张卡片。

2.0 改为**会话 1:1 常驻**：**只要是活跃的对话（正在执行或已出结论），卡片区域就有一张属于它的卡片**，实时反映该对话的状态，自动排序。用户不用打开每个对话就能在卡片区域看到"哪些对话在跑、哪些已出结论、哪些在等我"。

## 2. 核心概念：卡片 = 对话（1:1）

- 每个活跃对话**一张卡片**，卡片与对话一一对应；
- 同一对话的状态变化**更新同一张卡片**（不再产生多张）；
- 卡片区域 = 当前所有活跃对话的状态总览。

## 3. 五种状态定义与流转

| 状态 | 含义 | 图标 |
|---|---|---|
| **正在执行** | 对话正在运行（本轮 turn 未结束，agent 仍在干活） | **动态小圆环**（spinner，动画风格参考 DSH 自己的 loading 指示） |
| **有答案** | 本轮完成（turn/end completed）且无需回答 | 🟩 绿方块 |
| **有疑问** | 需要你回答（ask_user / 审批 / questions / 回复含疑问） | 🟠 问号 |
| **有异常** | 任务失败 / 异常结束 | 🔴 感叹号 |
| **正常** | 已完成（结论态）且用户已经看过/点过，不再需要特别关注 | ⚪ 灰白对勾/圆点（具体视觉待定） |

**状态流转**：正在执行 →（turn/end 或提问）→ 有答案 / 有疑问 / 有异常 →（用户看过）→ 正常。

## 4. 显示与隐藏规则

**显示**：所有活跃对话的卡片都显示，但以下情况会进入/隐藏为「正常」：

**隐藏条件（同时满足）**：
1. 该对话**不在执行过程中**（即已经是结论态：有答案 / 有疑问 / 有异常）；
2. 该对话的已完成状态**用户已经知道**（点击过卡片，或用户已进入该对话，使其变为「正常」状态）；
3. 该对话**已完成超过 10 分钟**（按进入结论态的时间计算）。

**状态变化**：
- 用户**点击结论态卡片**进入对话后，该卡片从「有答案 / 有疑问 / 有异常」变为「正常」；
- 「正常」卡片仍然显示在最后一组（让用户知道最近看过什么），直到满足上面的 10 分钟条件后自动隐藏；
- **正在执行的对话**：无论是否当前对话、是否点过，**始终显示**——因为本轮还没执行完，用户需要持续看到它还在跑。

**小结**：
| 卡片状态 | 显示位置 | 隐藏条件 |
|---|---|---|
| 有答案/有疑问/有异常（未看过） | 前面「需关注」组 | 不隐藏 |
| 正在执行 | 中间「执行中」组 | 不隐藏 |
| 正常（已看过） | 最后「已看过」组 | 已完成超过 10 分钟 |

## 5. 自动排序

- **三组顺序**：
  1. **需关注**：有答案 / 有疑问 / 有异常（未看过）——排在**最前面**；
  2. **执行中**：正在执行——排在**中间**；
  3. **已看过**：正常（已看过但未到 10 分钟隐藏）——排在**最后面**。
- **需关注内部排序**：按**时间先后**排队——谁先出现谁在前面（先到先排，队列式）；
- **执行中不排序**：正在执行的卡片自然排布即可；
- **已看过内部排序**：按进入正常/结论的时间排队即可；
- **动态迁移**：正在执行的对话完成后，卡片**自动从"执行中"移到"需关注"**（图标切换 + 排到需关注队列末尾，按完成时间）；用户看过后再从「需关注」移到「已看过」。

## 6. 卡片交互（延续 1.0）

- **点击结论态卡片** → 直达该对话（sessions.open），并把该卡片标记为「正常」（已看过）；
- **点击执行中卡片** → 直达该对话，但卡片**保留**（执行中例外，仍需持续显示）；
- **× 关闭** → **仅移除本次卡片**，不永久隐藏——该对话下次状态变化（执行态变化或出新结论）时卡片会重新出现；**执行态卡片同样可关闭**；
- **正常卡片**：不自动消失，但已完成超过 10 分钟后自动隐藏；
- **卡片数量**：无上限，超出屏幕也不裁剪；
- 拖动：1.0 已禁用，2.0 保持禁用。

## 7. 与 1.0 的差异对照

| 项 | 1.0 | 2.0 |
|---|---|---|
| 出现时机 | 出结论/提问/失败时 | 会话一活跃（开始执行）即出现 |
| 卡片数量 | 每事件一张（同会话可多张） | 每会话一张（1:1） |
| 状态 | 结论三态 | 五态（+正在执行动画 + 正常已看过） |
| 排序 | 按出现时间堆叠 | 自动分组：需关注在前、执行中在中、已看过在后 |
| 当前对话 | 不显示卡片 | 进入结论态对话会标记为「正常」；**执行态仍显示** |
| 消失 | 点击跳转（清该会话）/ × 关闭 | 点结论态变正常 + 完成超 10 分钟自动隐藏；× 关闭仍可用 |

## 8. 联动（声音 / 系统通知 / 去重）

- **声音**：正在执行**不响**（安静）；状态变化（执行→结论）时按结论类型响（当/当当/咚，沿用 1.x 判定）；
- **系统通知**：DSH 不在前台时，状态变化（执行→结论/提问）发系统通知（沿用 1.x 的 osascript / Windows toast + 可见性抑制）；
- **去重（仅声音层）**：**卡片没有去重概念**（1:1 卡片，同一对话只有一张，状态刷新即覆盖）；**声音仍然要去重**——防止同轮重复事件导致一直叮当叮当。沿用"同会话同内容 10s 窗口"的声音去重；跨轮/状态变化的声音照常响。

## 9. 已确认决策（2026-08-16）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 需关注排序 | 结论态（有答案/有疑问/有异常，未看过）按时间先后排队，在最前 |
| 2 | × 关闭语义 | 仅移除本次卡片，不永久隐藏；状态再变化重新出现；执行态可关闭 |
| 3 | 卡片数量 | 无上限，超出屏幕不裁剪 |
| 4 | 去重 | 卡片无去重概念；**声音层保留去重**（防叮当刷屏） |
| 5 | 执行态点击进入 | 执行态卡片即使进入当前对话仍显示（§4 例外），无需额外入口 |
| 6 | 已看过/正常 | 点击结论态卡片后变为「正常」，排在最后；完成超 10 分钟自动隐藏 |

## 10. 技术要点（实现方向）

- **host 会话状态跟踪**：从 `session/event` 推导每会话状态（turn/start → 执行中；turn/end/ask_user/approval/questions → 对应结论态），维护"会话 → 状态"映射；
- **卡片数据源**：新快照形状 = **每会话一张卡片**（状态 + 会话/工作区信息 + 更新时间），替代"事件队列快照"作为卡片渲染源；
- **client 渲染**：五态图标（含 spinner 动画）、三组排序、点击结论态标记正常、执行态保留、1:1 更新；
- **兼容改造**：1.0 的 feedback 引擎（声音/判定/去重/DND）、系统通知、深链直达继续复用，卡片层重构；
- **会话生命周期**：会话销毁/删除 → 对应卡片移除。

## 11. 验收标准（草拟）

- [ ] 对话开始执行 → 卡片区域出现该对话的执行态卡片（spinner 动画）
- [ ] 执行完成 → 同一张卡片变结论态并自动排到「需关注」最前
- [ ] 同一对话全程只有一张卡片（1:1）
- [ ] 点卡片进入结论态对话 → 卡片变「正常」并排到最后；进入执行中对话 → 卡片保留
- [ ] 正常卡片在完成超过 10 分钟后自动隐藏
- [ ] 声音/系统通知/直达行为与 1.x 一致

## 12. 对话自动命名（双入口：头部按钮 + 对话内指令）

> 新增需求 · 与 1.x 提醒/卡片/系统通知逻辑相互独立。

### 12.1 功能概述

为任意对话提供「自动命名」能力：根据对话内容自动生成简洁准确的标题，替代/更新当前会话名。两个触发入口（UI 按钮、对话内自然语言指令）**共用同一套命名逻辑**，产出风格一致。

### 12.2 入口一：对话头部操作按钮（UI 槽位）

- **位置**：`conversation.session.header.actions` —— DSH 标准 client 槽位，即「对话打开时标题旁的操作行」（additive list 类型，可注入多个按钮，按 `order` 排序）。dsh-dingo 以 client 插件注入一个「自动命名」按钮（如 ✏️ 图标或 "Auto" 标签，order 建议排在常规操作之后）。
- **运作流程**：
  1. 用户点击按钮 → client 调 host RPC `dingo.auto-name`（携带当前 `sessionId`）；
  2. host 执行命名逻辑（§12.4）→ 调用 `session.rename` 写入标题；
  3. 返回新标题 → client 弹提示「已重命名为：xxx」。
- **通用性说明**：`conversation.session.header.actions` 是 DSH **框架级槽位契约**——官方 Web UI 及任何基于标准 client 框架构建的界面都会渲染此按钮，**不限于某一特定外部界面**（这与左侧清单三点菜单不同：那是 UI 包内部硬编码、插件无法注入；头部操作行才是官方扩展点）。

### 12.3 入口二：对话内自然语言指令

- **触发**：用户在任意对话里发送类似「自动重命名这个对话」「给当前对话起个名字」「把这个对话命名为……」等指令。
- **运作**：DSH agent 识别到此类意图后，调用与按钮**同一个** host 命名服务（RPC `dingo.auto-name`，目标 sessionId = 当前会话）→ 生成标题 → `session.rename` → 在回复中告诉用户新标题。
- **说明**：此入口由 agent 理解自然语言后触发；与按钮共用 §12.4 的命名逻辑，保证两种方式产出一致。

### 12.4 统一命名逻辑（host 侧 `autoName(sessionId)`）

1. **读内容**：读取该会话近期消息（最近一轮或最近 N 条 user/assistant 消息）；
2. **生成标题**：归纳对话主题，产出 6~20 字（中文）或 3~12 词（英文）的简洁标题，风格接近人工命名；
3. **写入**：调用 `session.rename`（user 来源，标题固定、不被自动生成覆盖）；
4. **返回**：新标题（供按钮提示 / agent 回复）。

**生成方式**（可配置）：
- **LLM 生成**（默认，质量高）：把近期消息摘要 + 「生成会话标题」提示词交给模型，得到标题；
- **规则回退**（LLM 不可用时）：从消息提取关键词/首句/工作区名拼出兜底标题；
- 标题为空或不合格 → 保持原名并返回失败提示。

### 12.5 覆盖规则

- **仅在用户显式触发「自动命名」**（按钮或对话指令）时才生成并覆盖标题；不自动干预会话现有标题；
- 若生成结果不合格（空/过长/无意义），保持原名，提示失败原因。

### 12.6 技术要点

- **新增 RPC endpoint**：`/dingo.auto-name {sessionId}` → `{ ok, title? }`；
- **client 侧**：注入 `conversation.session.header.actions` 按钮（复用 dsh-dingo 现有 client 注入机制）；
- **host 侧**：会话消息读取（复用现有 apiProxy `sessions.history` 能力）+ 标题生成（LLM/规则）+ `session.rename` 调用；
- **与 1.x 关系**：独立新模块，不影响现有提醒/卡片/系统通知逻辑。

## 13. 卡片展示位置与形态（v2 定稿：挂载 header 公共槽位）

> 新增定稿 · 2026-08-16。取代 1.0 的"锚定 Session log 按钮 DOM"定位方式。

### 13.1 背景：1.0 定位方案的 bug

1.0 卡片用 `findSessionLogAnchor()` 定位——**全文档**找 `button, [role="button"]` 且文本含 "session"+"log" 的元素，锚定到其正下方。已确认的 bug：
- **误匹配**：右侧面板（aionui 预览/文件树）的节点是 `<button>`/`role="button"` 且带 `title=文件路径`——一旦预览的项目里有路径含 "session"/"log" 的文件，卡片会定位到面板里（看不到）；
- **位置漂移**：右侧面板打开/拖拽后 Session log 按钮位移，卡片虽每秒轮询刷新锚点，但误匹配/被遮挡仍会导致错位。

### 13.2 方案：卡片挂载到对话头部公共槽位

- 卡片容器通过 **`conversation.session.header.actions`** 槽位注入（DSH 框架级 additive list 槽位，即对话标题旁的操作行）；
- `order` 设为**负值** → 排在整个操作行**最左侧**（Session log 按钮左边）；
- 位置由槽位布局天然决定——**不再依赖 DOM 文本匹配**，面板怎么拖、按钮怎么动都不影响。

### 13.3 紧凑卡片（内嵌态）

- **内容**：仅状态图标（🟩 有回复 / 🟠 需回答 / 🔴 失败 / ⚪ 正常 / spinner 执行态）+ **工作区名·对话名**（限字截断）；
- **尺寸**：max-width ~130px 胶囊，超长省略号；高度对齐操作行；
- **无关闭按钮**（内嵌态不显示）；
- **点击** → 直达该对话（sessions.open + 按 §4/§6 规则标记/清除）。

### 13.4 溢出折叠 + 箭头展开

- **溢出检测**：`ResizeObserver` + `scrollWidth` 对比，放不下的卡片自动折叠；
- 折叠后尾部显示**箭头按钮 + 计数**（如 `+2`）；
- **点箭头 → 悬浮面板**（定位在操作行下方）：列出**全部**卡片，展开态用完整样式（200×56：状态图标 + 工作区名 + 对话名 + **× 关闭** + 点击直达），便于集中处理；
- 点击面板外部自动收起。

### 13.5 收益

1. **根治 1.0 定位 bug**（无 DOM 文本匹配、无漂移）；
2. **通用性**：走标准槽位，任何基于标准 client 框架的界面都生效（不限于特定外部界面）；
3. **为五态铺路**：执行态 spinner、正常态等全部在槽位内渲染，2.0 卡片重构无需再动定位。

### 13.6 技术要点

- **client 渲染拆分**：
  - `SessionCardRail`：header 内嵌组件（紧凑卡带 + 溢出折叠 + 箭头展开按钮 + 悬浮面板）；
  - 完整卡片组件复用（展开面板与内嵌共用数据，仅样式/交互差异）；
- **删除**：`findSessionLogAnchor` / `anchor` state / fixed 定位逻辑；
- **数据源不变**：`/dingo.feedback` 轮询快照（1:1 卡片列表）；
- **ResizeObserver** 监听容器宽度变化（面板开合/窗口缩放时重新折叠计算）。

### 13.7 验收标准（草拟）

- [ ] 卡片出现在对话头部操作行最左侧（Session log 按钮左边）
- [ ] 打开/拖拽右侧面板、预览含 "session log" 路径的文件 → 卡片位置稳定、不误匹配
- [ ] 紧凑卡片只显示状态图标 + 工作区/对话名（限宽截断），无关闭按钮
- [ ] 卡片超出槽位宽度 → 自动折叠为 `+N` 箭头；点开悬浮面板列出全部（含 × 关闭）
- [ ] 面板开合、窗口缩放时折叠状态实时更新
